Queue live acceptance procedure:
1. Pull ff2496f48f6539bda9fb0d053f970fdc4cef1354 or later.
2. Run typecheck/tests; stop on failure.
3. Deploy only with wrangler.staging.toml and confirm /health environment=staging.
4. Create a dedicated staging probe task in D1 with a valid UUID and status queued.
5. Insert an unexpired task_execution_leases row for that task with a distinctive probe lease token and lease_until in the future.
6. POST /api/v1/_staging/queue/replay with the staging API_TOKEN and the existing taskId.
7. After the consumer window, verify the task was not processed and the original active lease was not replaced. This is QUEUE_ACTIVE_LEASE_BLOCK PASS only if the real Queue message reached the consumer and the state stayed protected.
8. Change lease_until for the same task to a time in the past.
9. POST the exact same replay endpoint again.
10. Verify the consumer acquires a new lease, processes the task to a deterministic terminal/non-active state (for a deliberately nonexistent title, normally needs_source), then releases the lease row.
11. Only when both steps pass may QUEUE_IDEMPOTENCY become PASS (LIVE-STAGING).
12. Clean up the dedicated probe task/lease/test data.
